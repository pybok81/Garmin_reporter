# Garmin 훈련 리포트 앱 명세서

작성일 2026-11-15 · 대상 브랜치 `webapp` · 상태: 개인 사용 중(장기 사용하며 보완)

## 1. 목적과 범위

가민 데이터를 하루 단위 원본으로 저장하고, 그것으로 마크다운 리포트를 만들며, 리포트에 운동 메모와 AI 피드백을 붙이고, 쌓인 이력을 주·월 단위로 돌아보는 **개인용 브라우저 앱**.

- 사용자: 본인 한 명. 본인 PC에서만 접속(기본 127.0.0.1).
- AI 분석은 앱 밖에서 한다. 앱은 AI에 넘길 텍스트/파일을 만들고, AI의 답변을 받아 저장할 뿐이다. API 호출·과금 없음.
- 범위 밖(현재): 다중 사용자, 클라우드 호스팅, 가민 쓰기(데이터 업로드), 자동 AI 호출, 실시간 동기화.

## 2. 설계 원칙

1. **파일이 원본.** 리포트(.md)·피드백(.md)·보정(.json)·가민 원본(.json)이 진실의 원천. SQLite는 원본에서 다시 만들 수 있는 로컬 색인이며 git·Drive 동기화 대상이 아니다.
2. **가민 원본 JSON은 수정하지 않는다.** 사용자의 수정은 별도 파일(보정)로 덮어쓴다.
3. **표준 라이브러리만.** 서버는 Python 표준 라이브러리, 화면은 `webapp/index.html` 한 파일. 가민 수집만 외부 패키지(`garminconnect`) 사용.
4. **설치 최소화, 토큰 절약.** 큰 데이터는 파일/DB에서 코드로 집계하고, 대화에는 결과만 올린다.
5. **메모 보존.** 리포트를 다시 만들어도 메모 블록(`<!-- notes:ID -->…<!-- /notes -->`)은 유지된다. 줄바꿈(CRLF/LF)도 원본 그대로 보존한다.

## 3. 구성

| 파일 | 역할 |
|---|---|
| `app.py` | HTTP 서버, API, 폴더·설정·피드백 가져오기·동기화 조정 |
| `webapp/index.html` | 화면 전체(HTML/CSS/JS 한 파일) |
| `garmin_export.py` | 가민에서 하루 단위 원본 JSON 수집 (`data/raw/…`, 활동 상세 `details.json` 포함) |
| `garmin_report.py` | 원본 JSON → 마크다운 리포트 (메모 보존, 보정 적용) |
| `garmin.py` | export+report를 순서대로 부르는 CLI 진입점 |
| `corrections.py` | 가민 데이터 수정(보정) 저장·적용 |
| `history_db.py`, `import_export.py` | 이력 DB 스키마와 원본→DB 반영 |
| `history_view.py` | 이력 DB 읽기 전용 기간 요약(JSON/텍스트/CSV) |
| `names.toml` | 운동 코드→한글 이름, 부위 매핑 |
| `daily.bat` | Windows용 수집+리포트+열기 |

## 4. 데이터와 폴더

### 4.1 보관 폴더
`.env`의 `DATA_ROOT`(계정 설정의 "보관 폴더")로 지정. 비우면 앱 폴더. 지정하면 아래 폴더가 그 안에 놓인다.

| 폴더 | 내용 | 위치 |
|---|---|---|
| `reports/` | 날짜별 리포트 `YYYY-MM-DD.md` (`_backup/`에 덮어쓰기 전 백업) | 보관 폴더 |
| `feedback/<AI>/` | `YYYY-MM-DD.md` AI별 피드백 (`ChatGPT`, `gemini`, `claude` 등) | 보관 폴더 |
| `plan/`, `reference/` | 훈련 계획, 사전·기준표(RPE 등) 문서 | 보관 폴더 |
| `corrections/` | `YYYY-MM-DD.json` 가민 데이터 수정 | 보관 폴더 |
| `inbox/`, `archive/` | 피드백 투입 폴더, 월별 백업 zip | 보관 폴더 |
| `data/raw/…` | 가민 원본 JSON | **항상 로컬** |
| `data/history.db` | 이력 DB | **항상 로컬** |
| `outbox/` | AI에 보낼 번들 임시 파일 | **항상 로컬** |

- 앱은 보관 폴더를 일반 로컬 폴더로 읽고 쓴다. Drive 업로드는 Drive 데스크톱 앱의 역할이며 앱은 동기화를 하지 않는다.
- 이름이 `_`로 시작하는 하위 폴더(`_backup`, `_삭제`, `_이전`, `_반영됨`)는 목록에서 제외한다.

### 4.2 리포트 파일
- 운동 단위 섹션마다 메모 블록 `<!-- notes:<활동ID> -->`가 있고, 칸 레이블: 줄 단위 `레이블: 값`. 형식이 다른 줄은 `extra`로 보존.
- 오늘 날짜 리포트는 `⚠️ 오늘 스냅샷` 표시. 하루가 끝난 뒤 다시 만들면 갱신된다.

### 4.3 보정 파일 (`corrections/<날짜>.json`)
```json
{"date":"2026-11-11","updated":"…","activities":{"<활동ID>":{"sets":[
  {"i":3,"was":"DEAD_BUG","exercise":"BIRD_DOG","label":"버드독","reps":12,"weight_kg":0,"drop":false}]}}}
```
- `i`: 쉬는 세트를 뺀 운동 세트 번호(1부터). `was`: 수정 당시 원래 코드 — 가민에서 다시 받아 달라졌으면 적용하지 않고 경고.
- 리포트에서 수정된 세트는 ✎로 표시하고 무엇을 고쳤는지 적는다. 같은 보정을 DB 반영에도 적용한다.

### 4.4 이력 DB (SQLite, `data/history.db`)
테이블: `activities`, `daily`, `sleep`, `health_status`, `readiness`, `acute_load`, `vo2max`, `meta`. 단위: 초·미터·m/s, 시각은 KST.
- `activities`: 종류(`type_key`), 시간·거리·심박(평균/최대/최소)·칼로리·훈련효과·훈련부하·케이던스, 웨이트 총 세트/반복, 심박존 시간 `z0`(Z1 미만)·`z1…z5`(초).
- 반영은 하루 단위 upsert. 앱은 DB가 있을 때만 세트 수정·가민 가져오기 뒤에 자동 반영한다(실패해도 본 작업은 성공 처리).
- 앱은 DB를 **읽기 전용**으로 연다(기록 탭).

## 5. 화면 기능

### 5.1 공통
탭: 리포트 / AI / 리포트+AI / 기록. 오른쪽 끝 "문서 열기·닫기"로 문서 창 토글. 탭·문서 창 열림·AI 창 폭은 브라우저에 기억. 900px 이하에서는 세로로 쌓임.
헤더 버튼: 가민에서 가져오기, 피드백 반영, .md 파일 올리기, 계정 설정.

### 5.2 리포트
- 왼쪽: 주 단위로 접히는 날짜 목록(메모 채움 현황 뱃지, 휴식일, 오늘 표시). 선택한 날의 주는 자동으로 펼침.
- 본문: 리포트 렌더링, 운동별 메모 입력/저장(저장 전 이동 시 확인), 심박존 막대, 필요 시 "리포트 다시 만들기".
- **그래프**: 활동 상세 시계열(`details.json`)로 심박·페이스 선 그래프. 이동형 활동의 심박 급등 구간과 케이던스 락 의심을 표시. 웨이트에는 급등 감지를 하지 않는다.
- **세트 수정**: 운동 종류·반복·무게 변경, 세트 삭제, 모두 원래대로. 저장하면 보정 파일 기록 → 리포트 재생성 → DB 반영.
- **슈퍼세트 표시**: 비고에 슈퍼세트 묶음 추가.

### 5.3 AI
- 질문 선택/편집, "복사만 하기", AI 링크 열기(Claude/ChatGPT/Gemini, 목록 편집 가능), 팝업 창 옵션.
- 보낼 내용: 리포트 + 선택적으로 훈련 계획, 사전, 그래프 데이터(없음 / 튄 구간 요약 / 30초 단위 전체 표). "파일로 첨부" 옵션이면 번들을 파일로 만들어 내려받는다.
- **AI 피드백**: 탭(ChatGPT/gemini/claude + 파일로 발견된 AI). 붙여넣기 추가, 편집, 빈 내용 저장 시 삭제.

### 5.4 기록 (주·월 요약)
- 기간: 이번 주/지난주/이번 달/지난달/최근 4주/최근 90일, 날짜 직접 지정, ◀▶ 이동. 주는 월요일 시작. 최대 800일.
- 합계: 운동 횟수·활동일, 총 시간, 러닝 km, 웨이트 세트, 훈련 부하 합, 수면(시간·점수), HRV, 안정시 심박, ACWR, 심박존 시간(분). 각 항목에 직전 동일 길이 기간과의 차이.
- 종류별(러닝·웨이트·테니스·사이클·걷기·기타), 주별(15일 이상), 날짜별 목록. 날짜를 누르면 해당 리포트로 이동(리포트가 없는 날은 비활성).
- 내보내기: AI용 마크다운 텍스트 복사, CSV(날짜별 / 활동 전체, UTF-8 BOM).
- DB가 없으면 안내 문구만 표시.

### 5.5 문서 창
오른쪽 고정 패널(440px). 문서 종류: 훈련 계획, 사전·기준표. 목록 ↔ 보기, 새 문서·파일 올리기(드래그 앤 드롭 포함)·편집·삭제. 덮어쓰기는 `_backup`, 삭제는 `_삭제`로 이동.

### 5.6 가민에서 가져오기
날짜 범위(최대 31일) 지정 → `garmin_export.py` → `garmin_report.py` → DB 반영. 한 번에 하나만 실행. 로그인은 토큰 재사용, 최초/만료 시 비밀번호(·MFA) 입력.

### 5.7 피드백 반영
피드백 폴더(`.env` `FEEDBACK_INBOX`, 기본 `inbox/`), 구 `inbox/`, `feedback/` 루트, `feedback/<AI>/`의 `날짜_이름.md`를 읽는다. 파일명 허용: `2026-11-14_gpt.md`, `20261114_gpt.md`, `2026.11.14 gemini.md`. 해당 날짜 리포트가 있어야 하며, 처리한 파일은 `_반영됨/`으로 이동. 건너뛴 파일은 이유를 표시.

### 5.8 계정 설정
가민 이메일, 피드백 폴더, 보관 폴더(변경 시 기존 폴더 이동 처리), 백업 스냅샷 만들기(앱 시작 시 이번 달 것이 없으면 자동 생성), DB 상태와 "원본을 DB에 반영".

## 7. 보안·안정성

- 기본 바인딩 127.0.0.1, `Host` 헤더 허용 목록 검사, CSP·nosniff, `Cache-Control: no-store`.
- 파일 쓰기는 원자적(임시 파일 후 교체)과 잠금으로 보호. 가민 수집은 한 번에 하나.
- 가민 토큰과 `data/`, `.env`, DB는 민감 정보 — `.gitignore` 처리(`*.db`, `archive/` 포함). 비밀번호는 저장하지 않는다.
- 사용자가 만든 폴더 이름·파일명은 경로 이탈 검사를 거친다.

## 8. 알려진 한계

- 손목 광학 심박은 신뢰도가 낮다. 급등 감지는 "의심 표시"일 뿐 진위를 판정하지 않는다. 가슴 스트랩 도입 후 규칙 재정리 예정.
- 가민 비공식 라이브러리라 Garmin 변경 시 수집이 깨질 수 있다.
- Windows 경로·실제 Drive 폴더 동작은 개발 환경(리눅스)에서 직접 검증하지 못했고 사용자 PC 사용으로 확인 중.
- 최신 날짜 자동 반영·앱 시작 시 자동 반영은 미정(며칠 사용 후 결정).
- 자동화 테스트가 없다(수동·Playwright 점검). 코드 이해를 위한 구조 문서 미작성.

## 9. 향후 후보

보정 규칙 자동 적용 · CSV 변환기 확장 · DB 스냅샷의 다른 PC 공유 · 리눅스 서버용 rclone · 여러 AI 답변 종합 요약 · 단독 실행 앱 포장(설정 저장 위치·업데이트·자격 증명 보관 결정 필요) · 다크모드 토글 · `webapp` → `main` 병합 · 테스트 추가.
